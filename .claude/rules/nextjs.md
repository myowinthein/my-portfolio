# Next.js Rules

These rules govern how Next.js is used in this project. The architecture guide at `.claude/docs/nextjs.md` targets App Router on Next.js 15. This project uses **Pages Router on Next.js 13.0.2**. Most of that guide does not apply here.

---

## Router

Use Pages Router only. This project has three page files: `index.jsx`, `home-dark.jsx`, and `404.jsx`. Do not add new page files for new content sections. All content sections are `<TabPanel>` entries inside `home-dark.jsx`.

Never use:
- `app/` directory or App Router conventions
- Route groups, parallel routes, or intercepting routes
- `layout.tsx` / `template.tsx` / `loading.tsx` App Router files
- `"use client"` or `"use server"` directives — these are App Router constructs

## Rendering

All pages render as SSG (Pages Router default). No `getServerSideProps`, `getStaticProps`, or `getStaticPaths` are used — do not add them. All content is static or client-fetched.

## Components

All components are functional React components. There are no Server Components. Every component runs in the browser. Do not add class components.

`localStorage`, `document`, and `window` may be used inside `useEffect` without SSR guards because everything renders client-side.

The only SSR opt-out is the existing `dynamic(() => import('react-animated-cursor'), { ssr: false })` in `_app.jsx`. Use the same pattern if a future component is browser-only and cannot be guarded via `useEffect`.

## Data Fetching

The only runtime data fetch is the Medium RSS call in `AllBlogData.js`, done via `fetch()` inside `useEffect`. This is the correct pattern for this project.

For any new runtime data: use `fetch()` inside `useEffect`. Do not use SWR, TanStack Query, axios, or any data-fetching library. Do not add server-side data fetching.

## Server Actions

Do not add Server Actions. Next.js 13.0.2 does not support them.

## API Routes

Do not add API routes. There is no `pages/api/` directory and no need for one. External services (EmailJS, rss2json) are called directly from the client.

## Metadata / SEO

Use `next/head` via the existing `Seo.jsx` component — not the App Router Metadata API. All meta values come from `src/config.js`. Do not use `export const metadata`, `generateMetadata`, or `app/sitemap.ts`.

The sitemap and robots.txt are generated by `next-sitemap` via the `postbuild` npm script. Do not replace this with `app/sitemap.ts` or `app/robots.ts`.

## Images

Use `next/image` for all local images with a `sizes` prop for responsive hints. For external images (blog thumbnails), use a custom `loader` prop that passes the URL through unchanged — see `Blog.jsx` for the established pattern. Do not configure `remotePatterns` in `next.config.js` for external blog images.

## Fonts

Fonts (Poppins, Open Sans) are loaded via Google Fonts `@import` inside SCSS. Do not use `next/font` — it is not configured here and would conflict with the SCSS approach.

## Middleware

Do not add `middleware.ts`. This is a public portfolio with no auth and no locale routing.

## `next.config.js`

The config file is `.js` not `.ts`. `reactStrictMode: true` is the only setting. Do not add Turbopack, custom webpack config, or `output: "standalone"`.
